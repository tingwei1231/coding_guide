## 定義

用 parent 森林維護不相交集合。find 找代表根，union 合併兩個根；路徑壓縮讓沿途節點更靠近根，按大小／秩合併避免樹過深。

## 圖解

![Union-Find 並查集 的結構示意：root 0、1 -> 0、2 -> 0、root 3](/diagrams/union-find.svg)

初始 {0},{1},{2},{3}；union(0,1)、union(1,2) 後，find(0)=find(2)。再加入 (0,2) 沒有增加新連通群組，無向圖中會形成環。

## 複雜度

| 操作 | 成本 | 前提與說明 |
|---|---|---|
| 初始化 n 個元素 | O(n) | 每個元素起初是自己的根 |
| find／union | 攤銷 O(α(n)) | 同時使用路徑壓縮與按大小／秩合併 |
| 未優化的 find | 最差 O(n) | 可能退化成長鏈 |
| 儲存 parent 與 size | O(n) | 不保存所有圖的邊 |

## 適用情境

逐步加入無向邊時判斷連通、群組合併、Kruskal 的環檢測。只需要是否同集合，而非實際路徑時尤其合適。

## 常見誤區

union 前要找根，不能隨意把一個非根接到另一節點。普通並查集不支援刪邊後自動拆集合，也不能直接判斷有向圖的可達性。
