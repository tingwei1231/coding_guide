## 履歷

先讓讀者看懂你做過什麼、負責哪部分，以及能用什麼證據確認成果。新鮮人可使用課堂、社團與個人專案，不需要把練習包裝成正式工作。

一個專案條目可依序寫：要解決的問題、你的責任、具體實作與取捨、驗證結果。技術名稱應連到用途，例如「用索引降低指定查詢的掃描範圍」，比只列資料庫名稱更容易追問。

#### 改寫示例（虛構）

「熟悉 React，製作刷題網站」可改成「實作概念測驗的抽題、答案比對及重做流程；以鍵盤操作與重新整理案例驗證互動及狀態清除。」若提到速度、流量或改善百分比，附上測量條件；未測量就描述可觀察行為。

#### 常見錯誤

把團隊成果全部寫成個人成果、列出無法解釋的技術、只描述功能而沒有問題與證據、專案連結失效，以及在公開文件放入金鑰或他人資料。送出前逐項核對，並確認聯絡方式正確。

## 作品集

作品集可以先選一個能完整說明的專案，補足讓別人理解、執行與驗證的資料，再擴充功能。以下是可用來檢查自己作品的清單：

- README 說明目標使用者、問題、主要流程與目前限制。
- 提供清楚的安裝、啟動及測試指令，註明環境需求。
- 展示可公開的畫面或操作範例，並檢查展示網址可開啟。
- 指出你負責的部分及一個具體設計取捨，說明其他方案為何不適合當時需求。
- 保留有意義的測試與修復紀錄，能解釋哪些行為已驗證、哪些尚未覆蓋。
- 公開前檢查敏感資料、檔案授權與引用來源；範例資料使用合成內容。

若缺少可練習的專案，可把熟悉的日常流程縮成一個小工具，例如待辦篩選器或教材搜尋頁。先做出輸入、處理、輸出及錯誤情境完整的一條流程，再用 README 解釋範圍。這是練習方向，不要求購買服務或追逐特定技術。

## 前一週 checklist

1. 閱讀目標職缺內容，把要求對應到真實經驗；對不熟悉的項目列出可回答的範圍。
2. 選兩個專案，各整理問題、自己的角色、取捨、驗證方式及一次失敗經驗。
3. 完成[三個技術口述練習](/mock-interview)，用紙筆檢查例子，練習先講思路再講成本。
4. 準備五個行為題的真實素材，用 STAR 整理，但保留自然對話的彈性。
5. 用[概念測驗](/quiz)找出誤解，再回到對應模板複習，不只記住答案文字。
6. 檢查履歷與作品連結，確認公開內容、自己的貢獻及所有數字都有依據。
7. 確認已收到的面試通知，包括日期、時區、形式、地點或會議連結，以及對方要求的準備事項。

## 前一天 checklist

1. 再次核對時間、時區與聯絡方式；實體面試確認交通安排，線上面試測試麥克風、鏡頭及連線。
2. 準備履歷、專案摘要、紙筆，以及通知要求的工具或文件。
3. 試開專案展示與備用畫面；若服務無法使用，能用資料流程與測試紀錄說明設計。
4. 練習一段簡短自我介紹與一個專案故事，確認能分清自己和團隊的工作。
5. 整理想問對方的問題，例如日常合作方式、職責範圍及工作成果如何驗收。
6. 保留休息與出發緩衝時間，將最後複習集中在已知薄弱處。

這些清單供閱讀與自行核對，本站不儲存勾選或準備進度。完成後可回到[學習路徑](/roadmap)安排下一輪練習，或回到[模擬面試](/mock-interview)練習表達。
